# Performance comparisons

Run published competitors as black boxes. This tool never downloads source, changes other projects, enables Remote Automation, or changes security settings. Supply your own extracted Xbox maps. Keep configuration, apps, raw logs and game data outside git.

For a routed one-command refresh, add a private `route` object with `router`, `host`, `local_scratch` and `remote_scratch`. The router must map the scratch directories to one another. The command fetches explicit public live main into a detached source worktree in private scratch (reused for incremental builds, serialized by a task lock), builds through a `build` job, then runs the matrix through a `runner` job and fetches the generated summary/page. It stops on a failed build. The measured VISR path is bound to that build output. Transfer directories are unique per refresh; missing fresh output fails the command. The scratch paths must have the same mapping as the source worktree in the router. Routed sweep input paths refer to the local source; sweep import happens after collection. Completed source worktrees remain in private scratch for inspection and can be removed with normal `git worktree remove` when no job uses them.

For an already-routed job, build the live-main AppKit app with `python3 tools/macos_build.py --renderer metal --jobs 4` through the project job router. Copy `config.example.json` into private scratch, fill in paths and the exact build commit, and run on a quiet, dedicated Mac under the host job lock:

```sh
python3 tools/perf_compare/refresh.py refresh --config /path/to/private/config.json
```

The command fetches the newest matching published release, including prereleases (preferring `gh release download`; hosts without a GitHub CLI login use the public release API and asset URL without changing accounts); installs into private scratch; rotates three rounds of a10 and b30; imports the supplied sweep; writes `summary.json`; and regenerates `docs/benchmarks.md`. Exit 1 means at least one target is unavailable or incomplete. Exit 3 means a permission denial: stop and report the exact command and reason in the private `errors.json`. Do not work around it.

The default native setup reuses the earlier comparison's isolated data directories and console player-readiness probe. Configuration support differs among published apps: unsupported console/data-root overrides are an unavailable result. No edits to another app are made. Native scene and effective-resolution qualification requires a build-bound `qualification` record; numbers from unverified scenarios are excluded. The first matrix is a feasibility test until those qualifications pass.

Safari needs Remote Automation already enabled by the operator. Set a web target's private `unavailable_reason` to `safari-remote-automation-disabled` to preserve that prerequisite failure without contacting Safari. Every WebDriver session starts with clean storage, so the private target configuration must supply documented UI setup selectors and a `ready_selector`; it must arrange game data import and scenario selection within that session. A bare website or menu is never a game measurement. A private `qualification` record must bind the archive SHA-256, display rate and per-scenario effective resolution/cap to a visually verified setup. Requalify when the build changes. The runner does not read the site's JavaScript or WASM. Its entry HTML hash does not pin all fetched assets. A downloaded, versioned web release is preferable for later refreshes.

On current macOS, private `native_method = "metalperftrace"` enables per-frame metrics for the owned process through Apple's `metalperftrace setup`, collects only the sampling window, and reads the on-glass drawable timeline. It validates the recorded drawable size against the qualification, rejects multiple presentation layers, and keeps this method separate from HUD intervals. This avoids redacted console fields without changing system logging settings. See `metalperftrace --help` and `metalperftrace overview --help` for the installed tool's format.

The requestAnimationFrame probe measures browser callback scheduling, which can continue while the game repeats a frame. Metal HUD intervals measure the presentation stream Apple reports; GPU durations are discarded. Neither method establishes unique scanout frames. Keep these methods separate when interpreting results. The native xctrace Game Performance/Display fallback and physical-device Safari qualification remain phase 2; private WebDriver capabilities support assigned devices, with `device_slot` required. Vision Pro Remote Automation availability must be verified before use. Apple TV has no Safari target.

Default native conditions are 15 seconds of warm-up after readiness, then 60 seconds, three runs each with a requested 640×480-point window and 60 fps cap. On a 2× display the requested drawable is 1280×960. The native opening-sequence method includes cinematics and uses no input; other graphics settings retain the app's defaults. Set `native_scenario` to `opening-sequence` to record these limits in the page. Scene, camera and effective settings must be qualified per release. The tool refuses a locked display and waits up to 180 seconds for a two-second outside-process CPU sample to fall to one core or lower before the matrix. Load average is recorded for context; it can retain earlier work after a host becomes idle. During native sampling it checks background CPU separately from the game and rejects more than one background core on average. Safari retains only the initial quiet-host check; the job lock prevents competing routed Mac work. With private `cpu_policy = "baseline"`, the initial absolute CPU gate is replaced by a five-second sample immediately before each native sampling window; a run is rejected only when its average outside-process CPU rises more than half a core above that baseline. Steady background work remains active and can affect the estimates. The generated page records this method. It never unlocks the display or stops unrelated work. Thermal state comes from macOS `NSProcessInfo.thermalState`; raw `pmset` diagnostics stay private.

For native comparisons, private `frame_mode = "uncapped"` selects VISR's unlimited frame rate and OpenCE-macOS's documented `max_fps = -1`, with vsync disabled in both. Private `quality_preset = "matched-stock"` uses the documented stock-quality options listed on the generated page, including 128-pixel shadows and stock HUD/text. Unverified internal settings remain a limitation. The [OpenCE-macOS v1.0.2 user guide](https://github.com/channelramble/OpenCE-macOS/blob/v1.0.2/port/linux/README.md#settings) documents its configuration; VISR's options are in `port/ios/README.md`. Unsupported targets are rejected rather than assigned presumed settings.

Private `native_delay_seconds = 90` adds 90 seconds after warm-up; `scenarios = ["b30"]` selects the later beach window only. Keep mode, quality preset, warm-up and delay in the build-bound qualification. Capture both ends of each accepted window. All native results must have 1280×960 drawables. The scene's internal quality and AI progression still need visual review; equal elapsed time is not a deterministic replay. Active Safari targets reject native-only overrides.

Apple's on-glass drawable timeline can report intervals above the display rate with vsync off. These results are inverse trace-interval averages, not verified submission throughput or unique displayed FPS; their physical meaning above refresh remains unverified. Preserve each capped, uncapped and later-window target record separately when combining accepted summaries, and retain the prior sweep. The public table identifies each record's conditions.

The public summary (schema 2) holds one record per measured set, keyed by port, version, build, source, machine, OS, browser, method, conditions and date. Each record names the exact product version and bundle build (`CFBundleShortVersionString`/`CFBundleVersion` for Mac apps), the source commit (a release tag's commit for competitors, the measured VISR commit), the artifact and its SHA-256, and each sample carries the machine and OS. A refresh writes its own matrix to private `matrix-summary.json` and merges it into the public summary: new versions are added beside earlier ones, a record that already holds samples is never replaced, and only a same-key record without samples can be superseded. The page groups records by port and lists every measured version.

A routed refresh measures live main by default (labeled as a pre-release main build). Set private `route.ref` to a release tag such as `refs/tags/visr-v0.5.1` and `route.build_number` to that release's build number to build the tag with the release's optimization flags and build number, ad hoc signed. Private `release_cache` keeps downloaded release bundles apart from raw evidence, so the measured apps can load from the same storage.

For the OpenCE web build, private target keys drive the documented page flow: `import_file` (an operator-supplied disc image), `import_selector` and `import_ready_pattern` for the Game data chooser, `viewport` (640×480 points for 1280×960 canvases on a 2× display), `scenario_url` with the documented `?map={scenario}&play`, `ready_selector` and a fixed `load_seconds`. Each WebDriver session starts with empty site storage, so every round imports again; the first visit's cross-origin-isolation reload is awaited before the file is chosen. The build, channel, commit and network version come from the page's own About text and are recorded with each record.

CoreCE's Mac release (`corece`) uses the same isolated launch with two documented additions: `data_root`, a prepared folder whose `maps` is a real directory (an APFS clone), and `macos_settings`, which writes `macos-settings.json` with that `data_path` into the isolated save folder. Its uncapped mode is `frame_limit = 0` with `vsync = false`, from the settings file it writes. Release tags that are build numbers take the product version from the bundle's `CFBundleShortVersionString`.

Regenerate or check the page without running apps (Python 3.11 or newer, for `tomllib`):

```sh
python3 tools/perf_compare/refresh.py render
python3 tools/perf_compare/refresh.py render --check
```

### Results spreadsheet, snapshot and charts

Results live in a public Google Sheet; `docs/benchmarks.md` holds only headline charts and the methodology. Data and chart definitions change independently:

1. `sheet_export.py --output results.csv --sweep-output sweep.csv --layout-output layout.json` turns `summary.json` into the sheet's data. `results.csv` has one row per measured set and scenario window with these columns, in this order: `port`, `port_name`, `version`, `label`, `build`, `source`, `release_kind`, `artifact`, `artifact_sha256`, `host`, `platform`, `reference_box`, `machine`, `chip`, `memory_gb`, `os`, `browser`, `date`, `method`, `suite`, `window`, `scenario`, `delay_s`, `frame_mode`, `quality_preset`, `warmup_s`, `resolution`, `cap_fps`, `display_hz`, `rounds`, `fps_avg`, `fps_min`, `fps_max`, `fps_1pct_low`, `p50_ms`, `p95_ms`, `p99_ms`, `p99_ms_max`, `worst_ms_max`, `on_time_pct`, `thermal`, `status`, `notes`. Rates and intervals are means over the valid rounds; `fps_min`, `fps_max` and `p99_ms_max` give the spread. `platform` is Mac, iPhone/iPad, Apple TV or Vision Pro; `reference_box` marks the device each platform's headline chart uses (`REFERENCE_BOXES` in `sheet_export.py`; Apple TV has none yet); `fps_1pct_low` is 1000 divided by the 99th percentile interval. Hosts appear as chip and model (`M4 Mac mini`), never by name. `sweep.csv` is the device sweep. `layout.json` lists the tabs: `results` (the CSV), one `FILTER` tab per port, `device-sweep` and a `README` tab with a description for each column.
2. `sheet_fetch.py --gid <results tab gid>` downloads the `results` tab's public CSV into `docs/benchmarks/results.csv`, which is committed. It refuses a sign-in page, a different tab or a header that differs from the column list above. The page is rendered from this snapshot, never live from Google.
3. `docs/benchmarks/charts/<n>-<platform>.chart.toml` defines one platform's headline chart. Hand-written: `heading`, `paragraph`, `empty` (shown when the platform has no builds), `box`, `series_labels`, `rename`, and `[chart]` (`horizontal`, axis labels, `y_min`/`y_max`, legend `marks`, and `header`, the Mermaid frontmatter with the theme and plot colors). `[query]` selects data: `platform`, `metrics`, `port_order`, `filter` (column equals one of the values) and `no_data_reason`.
4. The entry model (`charts.py`, mirrored in `docs/site/benchmarks/benchmarks.js`): every port and version with rows on the platform is an entry. Its values come from the platform's reference box (`reference_box` is `true`) for the chosen suite: the mean of the windows' average rates and the median of their 1% lows, newest set per window. The newest build of each port is ticked by default; entries with no values are listed with the reason (`not_measured`, or `not_supported` for a status of that name, for example no split screen). `overall` takes the mean of the suites' averages and the median of their lows, and a build missing any suite has no overall bar.
5. `refresh.py render` writes `docs/benchmarks.md` (default view, Mermaid blocks between `<!-- BEGIN CHARTS -->` and `<!-- END CHARTS -->`, readable on GitHub) and `docs/site/benchmarks.html` plus `docs/site/benchmarks/results.csv` for Pages. The Pages version loads the pinned Mermaid (with a subresource integrity hash), reads the CSV, offers a suite switch and a checkbox list per platform, and keeps the selection in the URL hash (`#suite=overall&mac=<port>@<version>@<build>,...`; absent keys mean the defaults). `static_charts.py` pre-renders the default view to `docs/site/benchmarks/static-<platform>.svg`, the no-JavaScript fallback; rerun it (it needs Playwright) and commit the SVGs when the snapshot or a spec changes. `test_perf_compare_sheet.py` checks that the browser model and the Python model produce the same chart text for every suite when Node is installed.

Mermaid's `xychart-beta` draws no legend and overlaps bar series drawn together, so the headline charts put builds on the category axis and draw two series, average first and 1% low second, in `xychart-beta horizontal`: the shorter low bar sits over the average bar. A legend line of colored squares in the spec's `marks` order must match the `plotColorPalette` in the header.
